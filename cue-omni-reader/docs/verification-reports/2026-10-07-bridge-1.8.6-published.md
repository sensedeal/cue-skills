## What changed

Bridge 1.8.6 is a hygiene release; no tool-shape or wire-protocol changes.

- **Journal record GC:** long-lived installs accumulated a v5 record per parse, and every operation lookup scanned the whole directory. Terminal records are now deleted once their LOCAL retained result is provably unrecoverable — decided by the ArtifactStore's own 24h manifest expiry (`probeLocalResultExpiry`: retained / expired / unknown, conservative), never the remote 10-minute delivery window that the record's `resultExpiresAt` field carries. Records whose local copy is retained, unproven, or structurally untrustworthy are kept; the v3/v4/v5 record validators are reused so a corrupt-but-parseable record is never deleted. The sweep runs fire-and-forget at server startup and counts into `clean`. (The first cut of this GC deleted on the remote deadline — caught by review, fixed before release.)
- **save_result atomic export:** the export is written to staging and renamed into place. Windows cannot atomically overwrite, so a failed re-export keeps the previous export intact and surfaces `EXPORT_REPLACE_BUSY` instead of deleting the only committed copy; the destination is never unlinked and concurrent readers never observe a missing path. Crash-leftover `.tmp-export-*` staging files are swept after an hour.
- **Trust-pair advance:** the trusted managed-entry pair moves to **1.8.5 / 1.8.6** — a 1.8.4 entry is no longer a trusted managed entry; the only bare-`npx` Windows migration exception remains 1.5.1.
- The same promotion carries server-side changes (MR `!1022` encrypted/corrupt/xmind usage contract, MR `!1024` EFF-08 source-side color-token suppression) that do not alter the Bridge package or its tool surface.

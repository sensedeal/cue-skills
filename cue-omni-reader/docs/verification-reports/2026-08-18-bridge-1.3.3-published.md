## What 1.3.3 fixes (per the release basis)

1.3.3 is a doc-only patch on the 1.3.2 surface with **no tool-surface change and no code
change**. Two README passages had drifted from the project's own unified-Bridge design
decision (users see one omni-reader connector, never asked to distinguish URL vs local):

- "URLs never require installing Bridge. For local files, [...] install a pinned Bridge
  version." read as a decision tree (URL → skip Bridge, local → install Bridge). Rewritten to
  lead with installing Bridge as the default (it handles both source kinds through the same
  call), with the URL-only/no-Bridge path stated up front as the narrow exception, not buried
  after the install instructions where it read as a step during Bridge's own install flow.
  Confirmed live in the published 1.3.3 readme (see excerpt above).
- "Agents should not auto-split, transcode, or upload to public sites; ask the user for a new
  source" pushed `SOURCE_TOO_LARGE`/`UNSUPPORTED_MEDIA_TYPE` entirely onto the user. Bridge
  itself has no split/transcode tooling (verified: no such code exists in the package). The
  constraint is narrowed to what actually matters: never upload to a public site as a
  workaround, and never split/transcode silently — doing so is fine, but only after explicitly
  telling the user what's about to happen to their source and getting confirmation first.

Everything 1.3.2 documented remains true of 1.3.3: the six tool contracts are unchanged, the
`UNSUPPORTED_SOURCE` bare-envelope fix from 1.3.2 is present, and the legacy grant response
schema still accepts `omni.parse_grant.v2`.

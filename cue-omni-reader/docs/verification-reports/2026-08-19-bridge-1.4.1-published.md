## What 1.4.1 fixes (per the release basis)

1.4.1 is a doc-only hotfix on the 1.4.0 surface with **no tool-surface change and no
code change beyond the release-version literals**. The published 1.4.0 README never
listed `save_result` — Bridge MR !655 registered the seventh tool (with e2e tests
asserting the seven-tool surface) but deferred the skill tool-list entry and omitted
the README entirely, so the 1.4.0 readme documented only six tools while `tools/list`
exposed seven. 1.4.1 closes that drift:

- public tool list now includes `save_result`;
- the text-JSON bullet documents the `save_result` output (`path` and `bytes`; no path
  argument — the file is always named from `result_id` inside the Bridge cache's export
  directory, so it cannot be pointed at an arbitrary location; calling it again for the
  same result overwrites the same file);
- the Data handling section records that exports are independent of the 24-hour cache
  sweep — discarding the cached artifact or letting retention expire does not remove an
  export the user asked to keep.

Trust chain advanced to {1.4.0, 1.4.1}: `PREVIOUS_RELEASE_VERSION=1.4.0`,
`BRIDGE_RELEASE_VERSION=1.4.1`, uninstall/rollback recognize only a trusted 1.4.0 or
1.4.1 entry. All README version strings use `@1.4.1`. The full test suite passes
(522/522, including the trust-chain and README-metadata tests).

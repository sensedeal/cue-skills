## What changed

Bridge 1.8.5 is an additive release from the 2026-10-06 WorkBuddy dogfood session; no published error code was renamed and no tool shape changed.

- **New error code `KEY_DELIVERY_FAILED`:** a key arriving as an unexpanded placeholder, quoted text, or with stray whitespace fails before any network call, instead of surfacing as `INVALID_CUE_API_KEY`.
- **New error code `GRANT_SIZE_LIMIT_EXCEEDED`:** the service rejected the source's size at grant time (HTTP 413) — distinct from the 256 MiB Bridge preflight.
- **Deployment-tunable, clamped budgets:** `OMNI_FOREGROUND_BUDGET_MS` (5s–120s), `OMNI_STATUS_WAIT_MS` (1s–120s), `OMNI_INLINE_RESULT_MAX_BYTES` (1KiB–64KiB).
- **`setup --client workbuddy`:** first-class WorkBuddy target — an upgrade-resilient launcher entry, migration of hand-written pinned-node entries, carry-over of the user-managed key, and install-version verification.
- **`doctor --json` gains `client_adapters.workbuddy` and a real-process `stdio_probe` field** (newline-delimited `initialize` handshake against this package's own entry).
- Unavailable `OMNI_ALLOWED_ROOTS` entries are skipped instead of failing every parse with `INVALID_ALLOWED_ROOT`.
- `INVALID_GRANT_REQUEST` names every failing metadata field and its expected shape.
- **Trust-pair advance:** the trusted managed-entry pair moves to **1.8.4 / 1.8.5** — a 1.8.3 entry is no longer a trusted managed entry; the only bare-`npx` Windows migration exception remains 1.5.1.

## What changed

Bridge 1.8.7 keeps the frozen seven-tool surface. It explains a completed charge without writing billing text into the parsed content.

- **Content stays content.** Markdown, chunks, grounding, and saved files do not gain a billing summary. Agents append only `result.text`.
- **`billing.units` is optional structured detail.** When present, the closed set is seven nonnegative safe-integer counters: `document_class_pages_completed`, `primary_image_class_units_completed`, `additional_image_class_units_completed`, `cjk_codepoints_completed`, `other_codepoints_completed`, `normalized_units_completed`, `normalized_pages_completed`. `audio_ms_completed` and `video_ms_completed` appear only when that medium was measured. Zeros are kept. The settled `credits_charged` is not recomputed from these counters, and normalized counts are not added to pages.
- **Absence is not failure.** Remote URL results stay credits-only. A missing, timed-out, or malformed details response omits `units` and keeps the completed content and the returned credits. The bridge does not invent zero units.
- **Separate version axes.** Local output is `omni.local_bridge_tools.v6`. Capability and grant negotiation stay `omni.local_bridge_tools.v5`. The frozen SSE released event still rejects unknown fields, including a billing-units extension.
- **Restart keeps the detail.** A later process restores units from the local journal. Enrichment is monotonic: an absent record may gain units once, a later omission keeps them, and a conflicting set is rejected.
- **Trust-pair advance:** the trusted managed-entry pair moves to **1.8.6 / 1.8.7**. A 1.8.5 entry is no longer a trusted managed entry. The only bare-`npx` Windows migration exception remains 1.5.1.

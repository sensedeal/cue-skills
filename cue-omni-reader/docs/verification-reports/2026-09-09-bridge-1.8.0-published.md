## Update probe and reconnect guidance

Bridge 1.8.0 keeps the frozen seven-tool surface and the wire contract; it adds a **cheap, cached update probe** for agents and corrects the post-setup reconnect guidance.

- `doctor --silent-check` (optionally with `--json`) does **only** the local-version ↔ npm-`latest` comparison — no API, onboarding, or artifact work — and caches the verdict in `<artifactRoot>/version-check.json` for a 24-hour cooldown, so a once-per-session check never hammers the registry. It **fails open**: an unreachable registry or an unwritable cache never surfaces as a crash or a false "up to date" claim. Output is `{version_check, cached, upgrade?}`, where `upgrade` is the exact `npx -y @cueai/omni-reader-mcp@<latest> setup` command when the installed version is outdated. A cached verdict is trusted only for the **same installed version**, so an upgrade is never masked by a stale cache.
- The local `src/path-security.ts` extension allowlist is unchanged from 1.7.2 (archives `rar`/`tar`/`tgz`/`gz`/`bz2`; plain text `tsv`/`json`/`yaml`/`yml`/`toml`/`xml`/`ini`/`cfg`/`conf`/`log`; the RDF family; FreeMind `mm`; `parquet` and `xmind`/`mmap` deliberately unsupported).
- Post-setup guidance now says most clients only need a **reconnect** of the MCP server, not a full client restart (Claude Code / WorkBuddy: `/mcp` → `omni-reader` → reconnect). The trusted managed-entry pair advances to 1.7.3/1.8.0; the only bare-`npx` Windows migration exception remains 1.5.1.

## Optional inline `media_type` (client-side, ahead of the service)

Bridge 1.8.1 keeps the frozen seven-tool surface. It ships **client-side tolerance first**, so that a later service change cannot break an installed Bridge (expand/contract ordering).

- A completed or cleanup-pending remote inline result may carry an optional `media_type`. The accepted set is closed: `text/markdown; charset=utf-8` or the result-bundle label `application/vnd.cue.omni-result-bundle+json; version=1`. **An absent `media_type` means Markdown**, so every existing inline response is byte-for-byte unchanged; any other value is rejected as a contract mismatch.
- When a remote inline result carries exactly the result-bundle label, the Bridge verifies it as `omni.result_bundle.v1` and installs it as a local `kind: bundle` result. The visible text is the verified Markdown part, not the JSON envelope. If installation fails, the parse still completes with the original inline payload and a `delivery_warning`.
- **No Omni service emits the result-bundle label today.** Remote `detail=grounded|layout` therefore still fails closed with `UNSUPPORTED_DETAIL` before any operation is created, and the remote still produces Markdown only. This report makes no remote grounded/layout claim.
- `read_outline` is unchanged: it reads flat Markdown results and does not yet navigate a bundle directory (the same limit as a local grounded parse).
- A user-facing message is added for `media_too_long` (media longer than the parse limit).
- The local `src/path-security.ts` extension allowlist is unchanged from 1.7.2 (archives `rar`/`tar`/`tgz`/`gz`/`bz2`; `parquet` and `xmind`/`mmap` deliberately unsupported).
- The trusted managed-entry pair advances to 1.8.0/1.8.1; the only bare-`npx` Windows migration exception remains 1.5.1.

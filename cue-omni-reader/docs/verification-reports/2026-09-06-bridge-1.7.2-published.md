## Corrected user guidance

Bridge 1.7.2 keeps the seven-tool surface and wire contract from 1.7.1 unchanged — this is a client-side compatibility fix, not a protocol change. Its local `src/path-security.ts` extension allowlist, which rejects a source file before it is even sent (independent of what the L1 server can parse), now also accepts archive formats `rar`/`tar`/`tgz`/`gz`/`bz2` and plain-text formats `tsv`/`json`/`yaml`/`yml`/`toml`/`xml`/`ini`/`cfg`/`conf`/`log` plus the RDF family (`rdf`/`ttl`/`nt`/`n3`/`jsonld`) and FreeMind (`mm`) — all formats L1 already parsed by content-sniffing before this release; the allowlist had simply lagged behind server capability. `parquet` and mind-map container formats (`xmind`/`mmap`) remain deliberately unsupported: parquet falls through to L1's generic unrecognized-format rejection, and a synthetic `.xmind` zip was verified locally to be swept into the generic archive path, extracting internal `content.json`/`manifest.xml` as if they were the document rather than real mind-map content. The trusted managed-entry pair advances to 1.7.1/1.7.2; the only bare-`npx` Windows migration exception remains 1.5.1.

## What 1.9.0 changes for agents

- `parse` gains an optional `no_store` boolean (default `false`). The default
  lets the parsing service retain the parse result (content-hash keyed, per
  pod, TTL-bounded) so an identical re-parse is served from cache and billed
  the cache-hit rate. `no_store: true` forbids every cache read/write for that
  parse: always fresh, always full price. Completed local results disclose the
  choice in `data_handling.parse_result_cache`.
- Reuse and recovery honor the choice everywhere: explicit no-store requests
  never reuse or merge into cacheable operations; a later cacheable request
  waits out an in-flight no-store creation and reuses the settled record; a
  recovered `GRANT_PENDING` operation replays its own persisted choice.
- The URL lane is unchanged (no-store by API contract). Local Bridge tools
  remain seven; the remote MCP surface is unchanged.
- Billing facts stay settled operation snapshots: no reset, backfill, or replay.
